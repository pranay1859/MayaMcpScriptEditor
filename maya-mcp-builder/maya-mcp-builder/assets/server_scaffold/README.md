# maya-mcp

A FastMCP server that runs inside Autodesk Maya and exposes Maya commands as MCP tools. Designed to be controlled by Claude Desktop (or any other MCP client).

> Generated by the `maya-mcp-builder` skill. The threading model and transport are deliberate — see `references/architecture.md` in the skill before changing them.

## Requirements

- Autodesk Maya **2024 or newer** (ships with Python 3.10+; required by the `mcp` SDK).
- Network access for `pip install mcp` into Maya's site-packages **or** a virtualenv on Maya's `PYTHONPATH`.
- Node.js (only if you connect via `mcp-remote`, which is the default).

## Install

### 1. Install the `mcp` package where Maya can see it

Maya ships its own Python; you can install the package into Maya's site-packages or into a separate virtualenv that you add to Maya's `PYTHONPATH`.

**Option A — into Maya's site-packages (simplest):**

```bash
# Windows
"C:\Program Files\Autodesk\Maya2026\bin\mayapy.exe" -m pip install "mcp[cli]>=1.2.0"

# macOS
/Applications/Autodesk/maya2026/Maya.app/Contents/bin/mayapy -m pip install "mcp[cli]>=1.2.0"

# Linux
/usr/autodesk/maya2026/bin/mayapy -m pip install "mcp[cli]>=1.2.0"
```

**Option B — virtualenv on PYTHONPATH** (better for studios that don't want to mutate Maya's install):

```bash
mayapy -m venv ~/maya-mcp-venv
~/maya-mcp-venv/bin/pip install "mcp[cli]>=1.2.0"
# Then add ~/maya-mcp-venv/lib/python3.11/site-packages to Maya's PYTHONPATH.
```

### 2. Drop the `maya_mcp` package somewhere on Maya's `PYTHONPATH`

The simplest place:

- **Windows**: `Documents\maya\<version>\scripts\maya_mcp\`
- **macOS**: `~/Library/Preferences/Autodesk/maya/<version>/scripts/maya_mcp/`
- **Linux**: `~/maya/<version>/scripts/maya_mcp/`

For studio installs, set `MAYA_MODULE_PATH` and add a `.mod` file.

### 3. Tell Maya to autoload the server

Either:

- Copy `maya_mcp/userSetup.py` to the same `scripts/` directory (Maya autoloads it on startup), **or**
- Drop a one-liner into your own `userSetup.py`:
  ```python
  import maya_mcp; maya_mcp.start_server()
  ```

### 4. Start Maya

Watch the Script Editor for:

```
[maya-mcp] listening on http://127.0.0.1:6275/mcp
```

The chosen port is also written to `~/.maya-mcp/port` for clients to read.

## Connect from Claude Desktop

Copy `claude_desktop_config.example.json` into your Claude Desktop config (File → Settings → Developer → Edit Config). The default uses `mcp-remote` to bridge stdio↔HTTP:

```json
{
  "mcpServers": {
    "maya": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:6275/mcp"]
    }
  }
}
```

If your port differs (port collision fallback), update the URL accordingly.

Restart Claude Desktop. The Maya tools should appear in the "Tools" menu.

## Verify

In Claude Desktop, ask:

> List the scene objects in Maya.

You should see `list_scene_objects` get called and the four default cameras come back.

## Adding tools

1. Either add a function to `maya_mcp/tools/scene.py` / `mesh.py`, or create a new module at `maya_mcp/tools/my_module.py`.
2. Import `mcp` from `maya_mcp.server` and decorate with `@mcp.tool()`.
3. **Always import Maya modules inside the function body**, never at module top level.
4. **Always wrap the body in `bridge.run_main_thread(_do)`** — this is what keeps the Maya API on its main thread.
5. If you added a new module, add it to the import list in `maya_mcp/server._load_tools`.
6. Restart Maya.

See `assets/tool_template.py` in the `maya-mcp-builder` skill for the boilerplate.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Maya hangs on first tool call | A tool is calling Maya directly without `run_main_thread`. Fix the tool body. |
| `ImportError: No module named maya.cmds` | Your tool imported `maya.cmds` at module top level. Move the import inside the function. |
| Claude Desktop says "no tools" | Check the port matches between Maya's log line and `claude_desktop_config.json`. |
| Server doesn't start on Maya boot | Check Script Editor for a Python traceback from `userSetup.py`. |
